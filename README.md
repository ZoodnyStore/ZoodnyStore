# زودني Zoodny Store

متجر إلكتروني (HTML + CSS + JavaScript بدون أي build) يعمل على GitHub Pages، مع Firebase للحسابات والمحفظة والطلبات.

## هيكل المشروع

```
index.html                  الصفحة (HTML فقط)
css/
  main.css                  أنماط المتجر
  account.css               أنماط الحساب والمحفظة ولوحة الإدارة
js/
  core/images.js            مسارات الصور (تحمّل أولاً)
  firebase.js               تهيئة Firebase
  data/                     بيانات المتجر — هنا تعدّل المنتجات والأسعار
    apps.js                 شحن التطبيقات
    games.js                شحن الألعاب
    services.js             بريميوم + VPN + الدفع الإلكتروني
    products.js             المنتجات العامة
    categories.js           المنصات + التصنيفات + فئات الرصيد
  store/                    منطق المتجر
    state.js                الحالة وعناصر الصفحة
    notify.js               الإشعارات (showToast)
    catalog.js              عرض التصنيفات والمنتجات
    cart.js                 نوافذ الإدخال والسلة والدفع
    product-details.js      نوافذ تفاصيل المنتج
    main.js                 التهيئة عند تحميل الصفحة
  account/                  الحساب ولوحة الإدارة
    core.js                 الدخول، المحفظة، الشحن، سجل الطلبات
    admin.js                لوحة الأدمن
    service-modal.js        نافذة إدخال الخدمات
    mobile-nav.js           الشريط السفلي للموبايل
    product-manager.js      إدارة المنتجات من لوحة الأدمن
images/                     كل الصور
```

## ملاحظات مهمة

- **ترتيب ملفات `<script>` في `index.html` مهم**: ملفات `data` قبل `store`، و`account/core.js` قبل باقي ملفات `account`.
- **إضافة صورة جديدة**: ضعها داخل `images/` واكتب في المنتج `image: "images/اسم-الصورة.png"`
  (أو اسم الملف فقط من لوحة الأدمن — يُضاف `images/` تلقائياً).
- **تشغيل محلي**: افتح المجلد بأي سيرفر بسيط، مثلاً `python -m http.server` ثم `http://localhost:8000`.

## إدارة المنتجات من لوحة الأدمن

افتح الموقع ← **اضغط على الشعار 10 مرات بسرعة** أو **اضغط عليه مطوّلاً 4 ثوانٍ** ← سجّل الدخول ← تبويب **إدارة المنتجات**.
من هناك: إضافة / تعديل / حذف منتجات، أسعار، باقات، صور. التعديلات تُحفظ في Firebase
(`product_overrides` و `product_deletions`) وتظهر لكل الزوار فوراً، وتُحدَّث أسعار السلال المفتوحة تلقائياً.

**شرط ضروري — قواعد Firebase:** القواعد الكاملة موجودة في [`database.rules.json`](database.rules.json).
انسخ محتواه كاملاً إلى Firebase Console ← Realtime Database ← Rules ثم Publish.
القواعد تعرّف الأدمن بالـ uid ‏`GEO8okziO7cpgoKS39XBQxgrjVL2` — إذا تغيّر حساب الأدمن غيّر هذا الرقم في كل الملف.

### الإضافة السريعة من صفحات المتجر
عند تسجيل الدخول بحساب المدير تظهر بطاقة **"+ إضافة منتج جديد"** في آخر كل قائمة في المتجر.
داخل مجموعة باقات (مثل VPN أو بريميوم) تفتح البطاقة نفس المجموعة مع سطر باقة جديد فارغ.
(لا تظهر في "رصيد موبايل" لأن أسعاره ثابتة داخل الكود `creditAmounts`.)

### زر القلم ✎ على كل منتج
عند تسجيل الدخول بحساب المدير يظهر زر قلم أصفر في زاوية كل منتج في المتجر (وكل مجموعة باقات، وكل لعبة، وبطاقات التصنيفات في الصفحة الرئيسية).
يفتح نموذج التعديل الكامل لهذا المنتج مباشرة (الاسم، الأسعار، رأس المال، الصورة، الوصف، الباقات...) دون الدخول للوحة المدير.
باقة داخل مجموعة (VPN، بريميوم، دفع إلكتروني) تفتح نموذج المجموعة مع إبراز سطر هذه الباقة.
البطاقات تُربط بمنتجها في `catalog.js` عبر `pmgTagCard`، والزر نفسه في `product-manager.js`.
لا يظهر على "رصيد موبايل" (أسعاره ثابتة في الكود) ولا على بطاقات المنصات والمجموعات التي تضم عدة منتجات.

### تعديل التفاصيل مباشرة من نافذة المنتج
المدير عند فتح "تفاصيل المنتج" يرى قلماً بجانب الاسم والسعر والوصف والمميزات والصورة — يعدّلها في مكانها ويُحفظ التعديل لكل الزوار.
المميزات المعدّلة تُحفظ في الحقل `features` (قائمة نصوص)، وإن حُذفت كلها تعود المميزات الافتراضية. المنطق في `product-manager.js` (تغليف `showProductDetails` و `showPaymentProductDetails`).

### الطلب المباشر (بدون سلة)
لا توجد سلة: زر كل منتج اسمه **"طلب"**. المنتج الذي يحتاج إدخالاً (رابط، كمية، رقم لاعب، معلومة مطلوبة)
يفتح نافذته، وزر "طلب" فيها يرسل الطلب مباشرة للمدير ويخصم من الرصيد. المنتج بلا أي إدخال تظهر له نافذة تأكيد
قصيرة (السعر + الرصيد) حتى لا يُخصم المال بلمسة خاطئة. المنطق في `js/store/direct-order.js`،
وإتمام الطلب نفسه في `window.zoodnyPlaceOrder` (main.js).

### متطلبات المنتج (معلومة يرسلها الزبون)
في نموذج أي منتج (أو مجموعة باقات/لعبة/تطبيق): **"هل يحتاج المنتج معلومة من الزبون عند الطلب؟"**
اختر النوع (رابط، نص، بريد، هاتف، رقم) واكتب ماذا تطلب، ومثالاً وملاحظة اختيارياً.
عند إضافة المنتج للسلة — من أي صفحة — تظهر للزبون نافذة تطلب المعلومة (مع التحقق من صحتها)،
وتصل مع الطلب إلى لوحة المدير بجانبها زر نسخ. المنطق في `js/store/requirements.js`.

## بيع الجملة

- في نموذج المنتج: **سعر المفرق** و **سعر الجملة** (اختياري) — وكذلك لسعر الألف، وسعر الوحدة، وكل باقة/فئة.
- لوحة المدير ← **العملاء** ← زر **تفعيل الجملة** (أو من نافذة التفاصيل). يصل للعميل إشعار "تم تفعيل بيع الجملة".
- حساب الجملة يرى أسعار الجملة تلقائياً (البطاقات والتفاصيل والسلة)، والمنتج بلا سعر جملة يبقى بسعر المفرق.
- باقي العملاء تظهر لهم رسالة "هل أنت صاحب محل؟" مع زر واتساب عند تسجيل الدخول (أو مرة كل 3 أيام).
- لا يستطيع العميل تفعيل الجملة لنفسه: القاعدة `wholesale` في `database.rules.json` تسمح بتغييرها للمدير فقط.

## رأس المال والأرباح (للمدير فقط)

- في نموذج كل منتج حقل **سعر رأس المال** (وللسوشال ميديا: رأس مال الألف، وللتطبيقات: رأس مال الوحدة، ولكل باقة/فئة عمود "رأس المال").
- يُحفظ في `product_costs` — **قراءته للمدير فقط** (وليس في `product_overrides` العام)، فلا يراه الزبائن.
- لوحة المدير ← تبويب **المبيعات والأرباح**: الإيرادات، رأس المال، صافي الربح، الهامش، حسب المنتج والتصنيف واليوم، أفضل العملاء، وتفاصيل كل بيع — مع فلتر الفترة وزر **طباعة A4**.
- الربح يُحسب من الطلبات **المنجزة**. عند الضغط على "تم" تُثبَّت تكلفة الطلب في `order_costs`، فتغيير رأس المال لاحقاً لا يغيّر أرباح الطلبات السابقة.
- البنود التي لا يُعرف رأس مالها (رصيد الموبايل، الطلبات القديمة) لا تدخل في الربح، ويمكن إدخال تكلفتها يدوياً من صفحة التقرير.
- المنطق في `js/account/reports.js`. **يجب نشر `database.rules.json` الجديد** (أُضيف `product_costs` و `order_costs`).

## أدوات المدير والصلاحيات

- **حالة المنتج** (في نموذج كل منتج): متاح / نفذ المخزون (شارة مائلة على المنتج، يمكن رؤية التفاصيل لكن لا يمكن الطلب) / مخفي (لا يراه إلا المدير).
- **ترتيب الظهور**: رقم اختياري في نموذج المنتج — الأصغر يظهر أولاً.
- **نسخ منتج**: زر "نسخ" على بطاقة المنتج في إدارة المنتجات (ينسخ الباقات ورأس المال).
- **تعديل الأسعار دفعة واحدة**: زر في إدارة المنتجات — يطبَّق على القسم/التصنيف/البحث المعروض (نسبة أو مبلغ، مع تقريب ومعاينة).
- **تحذير الخسارة**: يظهر في النموذج إذا كان سعر المفرق أو الجملة أقل من رأس المال.
- **الموظفون** (أدوات المدير ← الموظفون): الموظف يسجّل حساباً عادياً ثم يُضاف بإيميله مع صلاحيات (الطلبات / شحن الرصيد).
  يفتح لوحته من زر "لوحة الموظف" في حسابه. لا يرى المنتجات ولا الأرباح ولا الأدوات. المسار `staff/{uid}`.
- **سجل النشاط** (`admin_log`): كل عملية من المدير أو الموظفين (أسعار، طلبات، شحن، أرصدة، حظر...) — يقرؤه المدير فقط.
- **حظر عميل** (`blocked_users/{uid}`): لا يستطيع الطلب ولا شحن الرصيد — القاعدة تمنعه فعلياً.
- **ملاحظة داخلية على الطلب** (`order_notes`): لا يراها الزبون.
- **تصدير Excel** (CSV) للطلبات وبنودها والعملاء وطلبات الشحن، و**نسخة احتياطية/استرجاع** للمنتجات والأسعار ورأس المال.
- المنطق في `js/account/admin-tools.js` و `admin.js` و `product-manager.js`. **يجب نشر `database.rules.json` الجديد.**

## استعادة كلمة المرور

- في نافذة الدخول: زر **"نسيت كلمة المرور؟"** تحت حقل كلمة المرور ← صفحة تطلب البريد ← زر **"استعادة"** ← Firebase يرسل رابطاً للبريد.
- المدير يستطيع إرسال الرابط لأي عميل من نافذة تفاصيل العميل ← "استعادة الحساب".
- **`reset.html`**: صفحة بتصميم المتجر وشعاره يفتحها رابط البريد لكتابة كلمة المرور الجديدة (مع مؤشر قوة وتأكيد)،
  ثم تُسجّل دخول العميل تلقائياً وتعيده للمتجر. تتعامل أيضاً مع تأكيد البريد. الرابط المنتهي يعرض زر "طلب رابط جديد" (`./?forgot=1`).
- **إعداد لمرة واحدة** (وإلا يفتح الرابط صفحة Firebase الافتراضية):
  Firebase Console ← Authentication ← Templates ← Password reset ← ✏️ ← **Customize action URL** ← `https://<موقع-المتجر>/reset.html`.
  وتأكد أن نطاق المتجر موجود في Authentication ← Settings ← **Authorized domains**.

## الإشعارات

- **جرس الإشعارات** في الشريط العلوي (للجميع): إشعارات الطلبات والرصيد للمستخدم، وإعلانات المدير لكل الزوار.
- **إشعارات الجهاز** (هاتف أندرويد / ويندوز / ماك) تظهر لمن ضغط "تفعيل" وموقع المتجر مفتوح عنده ولو بالخلفية.
  من كان الموقع مغلقاً عنده يرى الإشعارات في الجرس عند فتحه. آيفون: فقط بعد "إضافة إلى الشاشة الرئيسية".
- **تلقائياً للزبون:** بدء تنفيذ الطلب، إتمامه، رفضه (مع المبلغ المُرجع)، قبول/رفض شحن الرصيد، إضافة/خصم رصيد من المدير.
- **تلقائياً للمدير فقط:** طلب متجر جديد، طلب شحن رصيد، مستخدم جديد.
- **إعلان لكل العملاء:** لوحة المدير ← تبويب **إرسال إشعار** (فيه قوالب جاهزة). وبعد إضافة منتج جديد يعرض الموقع إرسال إشعار عنه تلقائياً.
- الملفات: `js/account/notifications.js` و `sw.js` (Service Worker للإشعارات فقط — لا يخزّن نسخاً من الموقع).
- مسارات Firebase: `notifications/{uid}` و `admin_notifications` و `broadcasts` — قواعدها في `database.rules.json`.

### إشعارات والموقع مغلق (Cloudflare Worker + Firebase Cloud Messaging)

المُرسل في `cloudflare/push-worker.js`. لا يقبل نص الإشعار من المتصفح، بل يقرأه من Firebase ويتحقق من هوية الطالب
(إشعار الزبائن والإعلانات للمدير فقط). الأجهزة تُحفظ في `push_tokens/{uid}`، والإعدادات في `config/push`.

إعداد لمرة واحدة:
1. **Firebase Console ← ⚙️ Project settings ← Cloud Messaging ← Web Push certificates ← Generate key pair** وانسخ المفتاح.
2. **Project settings ← Service accounts ← Generate new private key** (ملف JSON — سري، لا ترفعه على GitHub).
3. **Cloudflare ← Workers & Pages ← Create ← Hello World** باسم `zoodny-push` ← Deploy ← **Edit code**:
   الصق محتوى `cloudflare/push-worker.js` ← Deploy.
4. في الـ Worker: **Settings ← Variables and Secrets** أضف:
   `FIREBASE_SERVICE_ACCOUNT` (Secret = محتوى ملف JSON كاملاً)، `ADMIN_UID` (Text = معرّف المدير)، `SITE_URL` (Text = رابط المتجر).
5. افتح رابط الـ Worker في المتصفح — يجب أن يظهر `"configured":true`.
6. لوحة المدير ← **إرسال إشعار** ← الصق رابط الـ Worker والمفتاح ← حفظ ← **إرسال إشعار تجريبي**.

## الأمان

- دخول الأدمن يتم عبر Firebase Authentication فقط (حساب `admin@zoodny.com`) — لا توجد كلمة سر داخل الكود.
- الحماية الحقيقية للرصيد والطلبات والمنتجات يجب أن تكون في **Firebase Realtime Database Rules**
  (منع المستخدم من تعديل `balance` بنفسه، والسماح بالكتابة على `product_overrides` للأدمن فقط).
